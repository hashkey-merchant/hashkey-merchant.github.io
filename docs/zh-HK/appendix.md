# 附錄

## Canonical JSON

`canonicalJSON` 表示**規範化 JSON 序列化**。它的目的不是改變業務資料，而是把同一個物件穩定地序列化成唯一字串表示，用於：

- 計算 HMAC 請求本文雜湊
- 計算 `cart_hash`
- 避免因欄位順序不同導致簽章或雜湊不一致

### 規則

- JSON Object 的 key 按字母順序排序後再序列化
- Array 維持原有順序，不作排序
- 不加入額外空格、換行、縮排
- 相同語意的資料必須產生相同的序列化結果

### 範例

原始物件：

```json
{
  "b": 2,
  "a": 1,
  "nested": {
    "z": "last",
    "m": "middle"
  }
}
```

`canonicalJSON` 序列化結果：

```json
{"a":1,"b":2,"nested":{"m":"middle","z":"last"}}
```

> [!IMPORTANT]
> 商戶端參與簽章與雜湊計算時，應確保使用規範化 JSON，而非依賴不同語言預設的物件序列化順序。

## 錯誤碼

### 統一回應格式

```json
{
  "code": 0,
  "msg": "success",
  "data": { ... }
}
```

- `code = 0` 表示成功
- `code != 0` 表示錯誤，`msg` 欄位為英文錯誤描述

### 通用錯誤（1xxxx）

| Code | HTTP | 說明 | 排查建議 |
|------|------|------|---------|
| 10001 | 400 | 請求參數無效 | 檢查請求本文 JSON 格式與必填欄位 |
| 10002 | 401 | 未授權 | 檢查 HMAC 簽章或 JWT 是否正確 |
| 10003 | 404 | 資源不存在 | 確認資源 ID 是否正確 |
| 10004 | 409 | 資源衝突 | 檢查是否重複建立（如 `payment_request_id` 重複） |
| 10005 | 500 | 伺服器內部錯誤 | 聯絡技術支援 |
| 10006 | 403 | 無權限存取 | 檢查應用程式權限設定 |
| 10007 | 429 | 請求過於頻繁 | 降低請求頻率，稍後重試 |

### Cart Mandate 錯誤（4xxxx）

| Code | HTTP | 說明 | 排查建議 |
|------|------|------|---------|
| 40001 | 400 | 授權狀態無效 | cart mandate 已過期或已消耗（單次支付訂單同一 ID 只能使用一次） |
| 40002 | 400 | 支付類型不符 | 單次支付訂單只能用 `/orders`，可重複支付訂單只能用 `/orders/reusable` |
| 40003 | 400 | 授權已停用 | 聯絡管理員檢查 mandate 狀態 |
| 40004 | 400 | 授權已撤銷 | 該 mandate 已被撤銷，須重新建立 |

### 應用程式管理錯誤（5xxxx）

| Code | HTTP | 說明 | 排查建議 |
|------|------|------|---------|
| 50001 | 409 | 應用程式名稱已存在 | 更換應用程式名稱 |
| 50002 | 404 | 應用程式不存在 | 確認 `app_key` 是否正確 |
| 50003 | 403 | 無權存取 | 確認現時用戶是否有該應用程式的權限 |

### 錯誤排查建議

1. **先看 `code` 欄位** — 按錯誤碼範圍定位問題域（1xxxx 通用、4xxxx 購物車、5xxxx 應用程式）
2. **再看 `msg` 欄位** — 取得具體英文錯誤訊息
3. **檢查 HTTP Status** — 400 = 參數問題，401／403 = 認證／權限，500 = 伺服器端問題
4. **常見問題**：
   - `40001`：`cart_mandate_id` 已使用過，單次支付訂單每個 ID 只能支付一次
   - `40002`：使用了錯誤的 API（單次支付訂單與可重複支付訂單 API 不能混用）
   - `10004`：`payment_request_id` 重複，每筆支付須使用唯一 ID
